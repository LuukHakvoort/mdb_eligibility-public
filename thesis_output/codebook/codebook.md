# Codebook: `mdb_panel_final.csv`

Generated by hand (not auto-generated, so it can explain things in prose),
alongside `mdb_eligibility` (`../mdb_eligibility` relative to this
repository). Covers every column of `mdb_panel_final.csv` — the file at
`output/mdb_panel_final.csv` in this repository, identical to
`mdb_eligibility/data/output/mdb_panel_final.csv` — plus the companion
long-format file `output/unga_large_shareholder_distances.csv`.

One row of `mdb_panel_final.csv` = one (bank, recipient country, year). See
`largest_shareholders_by_bank.csv` / `largest_shareholders_summary.md` in
this folder for the "largest shareholder per bank, and whether it changes"
deliverable, and `variable_coverage.csv` for per-column non-null coverage
across the whole panel (18,368 rows as of the 2026-09-28 build). See
`../output/unga_positions_chart.png` (idealpointfp) and
`unga_positions_chart_idealpointall.png` (idealpointall) — each with its
own `..._data.csv` — for the recreated "MDB positions within the UNGA
country distribution" figure, one per measure (section 7).

**Build chain**: `mdb_eligibility/Makefile`'s `make final` target — see
`docs/CLAUDE.md` and `docs/coding_decisions.md` (2026-09-28 entry) in that
repository for the full account of every judgement call below.

## 2. Lending outcome

| Column | Type | Notes |
|---|---|---|
| `projects`, `projects_with_positive_amount` | int | Count of scraped projects for this dyad-year. |
| `any_lending` | 0/1 | `1` if `projects > 0`. Drives the zero-fill rule below. |
| `usd_nominal_total`, `usd_2025_total` | float, blank-or-zero | Total lending, nominal and inflation-adjusted to constant 2025 USD. **"0" means eligible with zero observed lending; blank means a genuine data gap** (2026-09-27 zero-fill rule) — **correction, 2026-10-04**: the 2026 lending dyad-years (291) carry `usd_2025_total = 0` because the deflator cannot price 2026, which is a data gap written as zero. Treat `usd_2025_total = 0` on 2026 rows as unpriced, not as zero lending; `ppp_2025_total` uses blank for these (see its row). See `docs/coding_decisions.md`, 2026-10-04. |
| `ppp_2025_total` | float, blank-or-zero | **PPP-adjusted** lending in constant 2025 international dollars (added 2026-10-04, a separate outcome alongside `usd_2025_total`). Same deflator and base year, so the two are directly comparable. Method: GDP price-level ratio (`NY.GDP.MKTP.CD / NY.GDP.MKTP.PP.CD`) for the recipient and approval year, not the official `PA.NUS.PPP` factor. "0" means eligible with zero observed lending, or a disclosed $0 project. **Blank means not priced**: any dyad-year with an unpriced project (146 dyad-years), and every year after 2025, because the FRED deflator has no 2026 value (all 291 lending dyad-years of 2026). Low-price-level recipients have PPP values 2–4× the nominal figure (India ~3.5×, Bangladesh ~3.6×); middle-income ones about 1.8×. |
| `afdb_ordinary_n`/`_usd`, `afdb_concessional_n`/`_usd` | float, blank for every bank but AfDB | AfDB's ordinary-window (non-concessional, "African Development Bank") vs. concessional-window ("African Development Fund"/ADF) lending, as columns on AfDB's one row rather than two competing bank codes — see `docs/coding_decisions.md`, 2026-09-28 (the AfDB/ADF merge). A project tagged with both windows in the source data adds to both sub-totals, so `afdb_ordinary_usd + afdb_concessional_usd` can exceed `usd_2025_total`. |

`".."` (WDI's own missing-value marker) was converted to blank, not zero.

**`log_population`, `log_gdp_ppp_per_capita`, `trade_openness`** (added
2026-09-30, hand-named rather than raw `wdi_<code>` style, per the user's
own request for clearer names): `log_population = ln(wdi_sp_pop_totl)`,
`log_gdp_ppp_per_capita = ln(wdi_ny_gdp_pcap_pp_cd)` (current-price, see
above), `trade_openness = wdi_ne_exp_gnfs_zs + wdi_ne_imp_gnfs_zs` (exports
+ imports, % of GDP). Plain arithmetic on columns already in this table —
a missing operand propagates to blank on its own, nothing is zero-filled;
`ln` is guarded against a non-positive input rather than silently emitting
`-inf`. `wdi_dt_tds_dect_gn_zs` (debt service) and `wdi_dt_dod_dect_gn_zs`
(external debt stocks) are retained as-is and never combined into either
of these, per the user's own instruction.

**`ucdp_armed_conflict`, `ucdp_war`, `ucdp_conflict_intensity`** (+ `_t1`
lags; added 2026-09-30, UCDP/PRIO Armed Conflict Dataset v26.1): whether
the recipient had an armed conflict-year (≥25 battle-related deaths),
whether it reached war intensity (≥1,000 battle-related deaths,
`intensity_level == 2`), and the yearly intensity itself (1=minor, 2=war —
**blank, not 0, whenever there's no conflict that year**, since 1/2 isn't a
scale with a meaningful zero). **Closed roster within the source's own
coverage window** (2002-2025 in this panel; 2026 is blank, outside what the
source covers at all) — a covered year with no listed conflict reads a
confident `0`, not blank, the one deliberate exception to this section's
usual "blank means no data" rule. This inherits UCDP's own documented
caveat that its coverage is "biased against the inclusion of conflicts in
the earlier decades and in the less-developed world" — flagged here, not
silently absorbed into the 0s. `location` (who the conflict's contesting
government is, comma-separated for interstate wars) credits every listed
country, per the user's own confirmed choice — UCDP's codebook is explicit
this is not necessarily the geographic location of fighting, though this
only affects the ~4% of conflict-years that are interstate; the rest are
intrastate/internationalized-intrastate conflicts naming exactly one
country. **No battle-death count column exists in this source** (that's
UCDP's separate Battle-Related Deaths dataset, not present here), so a
`ucdp_conflict_deaths` variable was not built — omitted, not proxied. See
`docs/coding_decisions.md`, 2026-09-30, for the full reasoning.

**`banking_crisis`** (+ `_t1` lag; added 2026-09-30, Laeven & Valencia's
Systemic Banking Crises Database 2026, IMF WP/26/94): whether the recipient
was in a systemic banking-crisis episode that year (coded directly by the
source via a documented multi-criterion definition — bank-run/loss
evidence plus a significant policy intervention — not inferred from a
debt/GDP threshold). Same closed-roster-within-coverage-window treatment as
`ucdp_*` above (2002-2025; 2026 blank). The source has **no currency-crisis
or sovereign-debt-crisis data and no IMF lending-arrangement (program)
data** — only a banking-crisis flag was built; `imf_program` and
`currency_crisis`/`sovereign_debt_crisis` are not available from any source
currently in `../Control variables/datasets/`.

**`press_freedom_score_legacy_2002_2021`, `press_freedom_score_2022_on`**
(RSF Press Freedom Index): two separate columns, never unified, because the
underlying index changed methodology at the 2021/2022 boundary — the legacy
score is lower-is-better on its own scale, the 2022+ score is a 0-100
higher-is-better composite. Real source gaps at 2001/2003/2011/2017 (files
never existed).

**`religion_government_restrictions_index`, `religion_social_hostilities_index`**
(Pew Global Restrictions on Religion): only covers 2007-2022 (source's own
range); blank outside it.

**`vdem_*`** (V-Dem, 11 curated indices out of ~4,000 in the full dataset):
`v2x_polyarchy` (electoral democracy), `v2x_libdem` (liberal democracy —
the headline "liberal" control), `v2x_partipdem`, `v2x_delibdem`,
`v2x_egaldem` (participatory / deliberative / egalitarian democracy),
`v2x_civlib` (civil liberties), `v2x_clphy` (physical-violence civil
liberties), `v2x_freexp_altinf` (freedom of expression & alt. information),
`v2x_corr` (political corruption), `v2x_rule` (rule of law), `v2x_gender`
(women's political empowerment). All V-Dem indices run roughly 0-1 unless
noted otherwise in V-Dem's own codebook.

**`leader_gender`, `leader_ethnicity`, `leader_birthplace`** (PLAD, the
Political Leaders' Affiliation Database): the head of state/government in
office as of 31 December of each year (a still-serving leader is treated as
ongoing through the panel's last year).

**`lgbti_progressive_score`, `lgbti_regressive_score`, `lgbti_composite_index`**
(LGBTI Policy Index, clean country-year source, no real gaps).

**`tourism_gdp_share_pct`, `tourism_seea_accounting_adopted`,
`tourism_employment_total_persons`** (UN Tourism): tourism's GDP share, a
0/1 SDG indicator (has the country adopted UN SEEA tourism-satellite
accounting), and total tourism employment (persons) — the last one is a
single aggregate, not broken out by sub-sector/gender.

**`eu_member`** (0/1, added 2026-09-28): was the recipient an EU member
that year — not EIB-specific, populated for every bank's rows. Sourced from
the same real-dated accession/exit spells (`eu_membership.csv`) already
used for EIB's own eligibility rule, so it can never disagree with that.
**A closed roster**: unlike every other column in this section, `eu_member`
is never blank — every country gets a confident `1` or `0` for every year.

**`wb_region`** (str, added 2026-09-28): World Bank region classification
(e.g. "Sub-Saharan Africa," "Europe & Central Asia"), static per country —
same value in every year of the panel. Sourced from the `Region` column of
a World Bank country-metadata file (a standard, static taxonomy, identical
regardless of which WDI indicator's download it ships with). ~99.4%
coverage — the small gaps are territories/dependencies/historical entities
the metadata file doesn't classify (Anguilla, the Vatican, Taiwan, etc.),
never guessed.

## 4. Project breakdown (sector / instrument / sovereign status)

Bank-country-year, re-aggregated from the scraper's own project-level data
— no new source, and zero-filled (not blank) wherever `any_lending == 0`
(a dyad-year with no lending has genuinely zero projects in every category,
which is different from a control variable's blank meaning "no data" — see
`merge_control_panel.py`'s docstring).

- **`sector_<category>_n`** (31 columns): count of projects in each DAC/
  IATI-style sector category (e.g. `sector_agriculture_n`,
  `sector_transport___storage_n`, `sector_water_supply___sanitation_n`).
  Column names are the source's own sector-category text, lowercased and
  non-alphanumeric characters collapsed to underscores.
- **`instrument_<type>_n`/`_usd`** (8 types): loan, technical assistance,
  grant, trade finance, equity, guarantee, other, unspecified — count and
  constant-2025-USD amount per type.
- **`sovereign_n`/`_usd`, `non_sovereign_n`/`_usd`, `unknown_n`/`_usd`**:
  the same split by borrower type (sovereign vs. non-sovereign lending).

## 5. UNGA independent variables (this build's new work)

Built from Erik Voeten's UNGA ideal-point estimates (`Datasets/
dataverse_files (1)/IdealpointsJuly2025.dta` in this repository — country-
year, `idealpointall`/`idealpointfp` on Bailey-Strezhnev-Voeten's usual
scale). **`idealpointfp` extends through 2025** (via a companion release,
the user's explicit choice — see `docs/coding_decisions.md`, 2026-09-28,
for the vintage-mismatch trade-off that was weighed and accepted).
**`idealpointall` has real coverage only through 2023** — not 2024: the
raw `.dta` itself has zero non-null `idealpointall` values for 2024, a
genuine property of that release (the all-votes measure needs more raw
vote data than final-passage and evidently lags behind even within one
release), not a processing gap. **All `unga_*` columns are left blank,
never zero-filled, when an operand is missing** — a UNGA distance is never
a real, countable zero the way a lending count is.

### 5.1 Concept

Every construction is a **distance**: `|recipient's own ideal point −
reference point's ideal point|`, computed separately for `idealpointall`
and `idealpointfp` (suffix `_all`/`_fp`), and separately at `t` (=`year`)
and `t-1` (=`year - 1`, **both** the recipient's and the reference point's
ideal points are re-evaluated a year earlier, not just one side). Four
reference points, per (bank, year):

1. **Hegemonic** (`unga_hegemonic_*`): the bank's single largest
   shareholder that year, by decision-making weight (see 5.2). A structural
   fact about the bank — computed even when that shareholder has no UNGA
   data that year (in which case only the distance is blank, not the
   shareholder's identity).
2. **G7** (`unga_g7_*`) / **G10** (`unga_g10_*`): a vote-power-weighted
   average ideal point across whichever G7 (Canada, France, Germany, Italy,
   Japan, UK, US) or G10 (the same seven plus Belgium, Netherlands,
   Switzerland, Sweden — the standard 11-member IMF/BIS "Group of Ten")
   members are shareholders of that bank that year. Fixed, real-world
   political/financial groupings — **not** redefined per bank.
3. **Large shareholders** (`unga_ls_*`): the same weighted-average
   construction, over shareholders holding more than **5%** of the bank's
   raw decision-making weight that year (`LARGE_SHAREHOLDER_THRESHOLD_PCT`
   in `scripts/build_unga_iv.py` — one named constant, easy to change).
   Individual (not just averaged) distances to each qualifying large
   shareholder are in the companion file, section 6 below.
4. **Coalition** (`unga_coalition_*`): the same, across *every* shareholder
   of the bank that year.

**The recipient is never excluded from a pool for being a shareholder of
its own bank** (common for regional banks — AfDB, AsDB, IDB, CABEI, EBRD
all have borrowing members who are also shareholders) — the user's own
confirmed choice. This is why the reference-point computation is a pure
function of (bank, year) with no notion of "the recipient" at all: a
recipient who happens to be a large shareholder is automatically part of
its own comparison point, not a special case.

### 5.2 Shareholder weight (feeds all four constructions)

From `data/extracted/shareholder_weights.csv` in `mdb_eligibility`
(`scripts/build_shareholder_weights.py`), not exposed directly in this
panel but underlying every `unga_*` column:

- **Weight = `voting_power_pct`, falling back to `capital_share_pct`** when
  voting power was never published for that bank (EIB, always) or that
  bank-year. Without the fallback, EIB would have zero coverage anywhere in
  this section.
- **Carried forward (LOCF)** across years with no snapshot, within a
  contiguous run of confirmed-member years for that (bank, country) pair —
  never across a year the country actually left the bank. This is a rule
  specific to this derived file; the underlying `membership.csv`/
  `shareholders_panel.csv` are never interpolated.
- **Renormalized to sum to 1** within whichever pool (G7-present, G10-
  present, >5%-present, or all shareholders) is being averaged, among
  shareholders that have *both* a weight and UNGA data that year — a
  shareholder with a weight but no UNGA coverage is skipped, not treated as
  zero-weight. Matters most for EBRD, whose country shares sum to only
  ~93-94% (the EU and EIB hold shares as excluded institutional members).

Bank-year reference points, each repeated for `t` and `t1` (42 columns —

| Column pattern | Notes |
|---|---|
| `unga_largest_shareholder_iso3_<lag>` | The hegemonic reference's identity. |

| `unga_hegemonic_ip_all_<lag>`, `_fp_<lag>` | That shareholder's own ideal point (blank if it has none that year). |
| `unga_g7_ip_all_<lag>`, `_fp_<lag>`, `unga_g7_n_shareholders_all_<lag>`, `_fp_<lag>` | G7-present weighted ideal point + how many G7 members qualified. |

**The `_n_shareholders_all`/`_n_shareholders_fp` split matters**: `idealpointall`
and `idealpointfp` coverage can genuinely differ within the same bank-year
(most visibly for 2024-2025, where `idealpointall` has none at all), so
each measure's weighted average is computed only over shareholders that
actually have *that* measure — not a shared count across both.

Distances (20 columns — the headline regression variables; everything
above is transparency/robustness-check material):

| Column pattern | = |
|---|---|
| `unga_hegemonic_dist_all_<lag>`, `_fp_<lag>` | `\|unga_recipient_ip_*_<lag> − unga_hegemonic_ip_*_<lag>\|` |
| `unga_g7_dist_all_<lag>`, `_fp_<lag>` | vs. `unga_g7_ip_*_<lag>` |
| `unga_g10_dist_all_<lag>`, `_fp_<lag>` | vs. `unga_g10_ip_*_<lag>` |
| `unga_ls_dist_all_<lag>`, `_fp_<lag>` | vs. `unga_ls_ip_*_<lag>` |

`<lag>` ∈ {`t`, `t1`} throughout.

### 5.4 Known coverage boundaries (real, not bugs)

- **`_fp` columns reach 2026's `t1` (=2025); `_all` columns don't reach
  past 2023's `t` at all.** `idealpoint_fp` is extended to 2025 via a
  companion release (a different *release* of Voeten's model than the
  main `.dta` — highly correlated, r=0.9996, but not identical; a small
  vintage difference, not a rescaling — the user's explicit, informed
  choice, see `docs/coding_decisions.md`, 2026-09-28, for the full
  numbers). `idealpoint_all` has zero coverage in the source `.dta` itself
  for 2024 (confirmed directly against the raw file — a genuine property
  of that release, not a gap in this pipeline), so its real cutoff is 2023.
- **G7/G10 coverage is lower than coalition/hegemonic/large-shareholders**
  (~66-72% vs. ~84-91% of rows, see `variable_coverage.csv`) simply because
  far fewer countries qualify for those two fixed pools per bank.
- **A few banks show a single-year flip** between two closely-matched top
  shareholders (e.g. AfDB: Nigeria 2002-2010, Japan 2011, Nigeria
  2012-2026) — a real feature of razor-thin top-2 races in the published
  percentages, not a bug. See `largest_shareholders_summary.md`.

## 8. Other-MDB lending (H4 instrument)

Added 2026-09-30. Needs no external dataset — derived entirely from this
panel's own lending totals (`mdb_eligibility/scripts/build_other_mdb_
lending.py` + `merge_other_mdb_lending.py`). For a given (focal bank,
recipient, year), the **pool** is every *other* bank with its own eligible
row for that exact (recipient, year) — a bank with no row there wasn't part
of the pool at all (structurally couldn't have lent, not a missing
observation), consistent with this project's framing of eligibility as a
sample restriction.

| Column | Notes |
|---|---|
| `other_mdb_usd_t1` | **Use this one in regressions.** Sum of the pool's `usd_2025_total` in year *t-1*, blank components treated as 0. |
| `other_mdb_usd_millions_t1`, `ln1p_other_mdb_usd_t1` | `/1e6` and `ln(1 + other_mdb_usd_t1)` convenience transforms of the column above. |
| `other_mdb_usd_strict_t1` | The same sum, but blank if **any** pool member's own `usd_2025_total` was itself a genuine data gap (not zero lending) — a robustness-check companion, not the default. |
| `other_mdb_n_eligible_t1`, `other_mdb_n_missing_amount_t1` | Coverage diagnostics: pool size, and how many of the pool had a blank amount. |
| `other_mdb_ppp_t1`, `other_mdb_ppp_millions_t1`, `ln1p_other_mdb_ppp_t1` | **PPP-adjusted** counterpart (added 2026-10-04), built from `ppp_2025_total` on the same pool and lag. An unpriced pool member (blank PPP) counts as 0 here, as in the USD version, so the total is systematically lower where unpriced projects exist. |
| `other_mdb_ppp_strict_t1`, `other_mdb_ppp_n_missing_amount_t1` | PPP strict total (blank if any pool member is unpriced) and the count of unpriced pool members. |

An empty pool (`other_mdb_n_eligible_t1 == 0`, no other bank eligible there
that year) is a real, countable `0` for both totals, not blank — there's
nothing to be missing. Lag direction: "lending by other banks in year t-1
predicts the focal bank's lending in year t," the same `_year_m1`-style
shift used throughout section 5.

## 9. Bank classification (`bank_classification.csv`) — not a panel column

Added 2026-09-30, `mdb_eligibility/data/manual/bank_classification.csv`. A
**separate, bank-level metadata table**, deliberately not merged into
`mdb_panel_final.csv` — a time-invariant column isn't an estimable
regressor within this project's per-bank regressions, so it's kept as its
own small reference table instead, per the user's own instruction.

Rebecca Ray's (2021) governance typology (*"Who controls multilateral
development finance?"*, Global Governance 27(1): 118-143) — three types,
by Gini-index concentration of power-weighted votes vs. power-weighted
borrower Board representation: **creditor-led** (IBRD, IDA, EBRD, IDB,
AsDB), **core borrower-led** (AfDB, IsDB, AIIB, EIB, CDB), **mutual
aid-oriented** (CABEI, CAF). Two of this project's 14 canonical banks
aren't named in the excerpt of Ray (2021) available while building this —
**NDB and BADEA's classifications were supplied directly by the user**
(NDB = core borrower-led, BADEA = creditor-led), not inferred by name; the
table's own `classification_source` column keeps this distinction explicit
rather than implying Ray's paper itself covers all 14. CDB's classification
is read as the Caribbean Development Bank (this project's canonical CDB)
from context in Ray's own list of small regional borrower-led banks — a
confident but not independently re-verified reading, flagged in the
table's `note` column.
